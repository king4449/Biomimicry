2.2 BGP RPKI & OSPF Authentication 🔴 Advanced

To stop forged announcements, routes must be validated with RPKI (BGP ROV) and OSPF messages must be authenticated with HMAC-SHA-256. (Syntax varies by platform and release.)

! Cisco IOS-XE: BGP origin validation (ROV) — RFC 6811 / RFC 8210
router bgp 65000
 ! RTR session to the RPKI validator (port depends on the validator)
 bgp rpki server tcp 192.168.1.100 port 323 refresh 600
 neighbor 203.0.113.1 remote-as 64500
 address-family ipv4 unicast
  neighbor 203.0.113.1 route-map RPKI_FILTER in
!
route-map RPKI_FILTER deny 10
 match rpki invalid
route-map RPKI_FILTER permit 20
!
! OSPFv2 HMAC-SHA-256 authentication (RFC 5709)
key chain OSPF_KC
 key 1
  key-string SECURE_KEY
  cryptographic-algorithm hmac-sha-256
interface GigabitEthernet0/0
 ip ospf authentication key-chain OSPF_KC
⚙ Red Team (OSPF Poisoning with Scapy)from scapy.contrib.ospf import OSPF_Hdr, OSPF_LSUpd, OSPF_Router_LSA
pkt = IP(dst="224.0.0.5", proto=89)/OSPF_Hdr(src="10.0.0.1")/OSPF_LSUpd(lsalist=[OSPF_Router_LSA(linkcount=1)])

3.2 S3 Object Lock & WORM 🟡 Intermediate

In the cloud, immutability is enforced with AWS S3 Object Lock (Compliance mode). Object Lock requires versioning; enabling it when the bucket is created is recommended (since November 2023 AWS also allows enabling it on existing buckets).

# 1. Create the bucket (Object Lock enabled)
aws s3api create-bucket --bucket company-critical-backup \
    --object-lock-enabled-for-bucket

# 2. Upload an object + 10-year retention (legal retention)
aws s3api put-object \
    --bucket company-critical-backup \
    --key db_backup_2026.bak \
    --body local_file.bak \
    --object-lock-mode COMPLIANCE \
    --object-lock-retain-until-date "2036-10-07T00:00:00Z"
# Until the date passes, nobody (root included) can delete the locked version.
# An overwrite only creates a new version; the locked version is kept.
⚙ Red Team (Targeting VSS)
  1. Unable to touch S3, the attacker goes for local shadow copies: vssadmin delete shadows /all /quiet
  2. Blue Team: Recovers within the RTO from immutable hypervisor snapshots.

5.2 Blocking Execution with eBPF LSM 🔴 Advanced

The closest counterpart of the CRISPR-Cas scissors is not a read-only kprobe but a BPF LSM (Linux Security Module) hook. With the bprm_check_security hook an execve() call can really be denied (-EPERM). It needs Linux 5.7+, CONFIG_BPF_LSM and the lsm=…,bpf boot parameter.

/* eBPF LSM: denies a suspicious exec inside the kernel (skeleton) */
#include "vmlinux.h"
#include <bpf/bpf_helpers.h>
#include <bpf/bpf_tracing.h>
#define EPERM 1

SEC("lsm/bprm_check_security")
int BPF_PROG(check_exec, struct linux_binprm *bprm, int ret) {
    char buf[128];
    if (ret) return ret;          /* keep the earlier LSM verdict */
    bpf_probe_read_kernel_str(buf, sizeof(buf), bprm->filename);

    if (is_denied(buf)) {         /* placeholder: policy lookup in a BPF map */
        bpf_printk("CRISPR: exec denied: %s", buf);
        return -EPERM;
    }
    return 0;
}
char LICENSE[] SEC("license") = "GPL";
⚙ Red Team (Buffer Overflow)
  1. The attacker gets RCE and calls execve("/bin/sh").
  2. The LSM hook fires inside the kernel; -EPERM is returned and the request is denied before the new program is loaded.
  3. The service keeps running without a restart; the underlying vulnerability must still be patched.

6.2 AES-GCM and the Avalanche Effect 🟡 Intermediate

The AES block cipher alone gives only confidentiality. For integrity, GCM produces an authentication tag. The same key+nonce pair must never be used twice.

# Python AES-GCM (cryptography library)
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
import os

key = AESGCM.generate_key(bit_length=256)
aesgcm = AESGCM(key)
nonce = os.urandom(12)  # 96-bit; NEW for EVERY message

data = b"Secret_Data_1"
ciphertext = aesgcm.encrypt(nonce, data, None)
# Output = ciphertext + 16-byte auth tag

plaintext = aesgcm.decrypt(nonce, ciphertext, None)
⚙ Avalanche Effect — AES block levelBlock 1: "Vault_Passwd:000"
Block 2: "Vault_Passwd:001" (one bit differs)
* When a single AES block is encrypted with the same key, about 50% of the output bits change on average.
* Note: GCM is counter (CTR) based; with the same nonce a one-bit difference changes only that bit of the output. That is why the nonce must be unique per message; integrity comes from the tag.

7.2 K8s NetworkPolicy 🟡 Intermediate

In Kubernetes, traffic between pods is allowed by default. For Zero Trust a default-deny policy is applied first, then only the required flows are allowed. A CNI that enforces NetworkPolicy (Calico, Cilium, etc.) is required.

# 1) Namespace-wide default deny (the dam)
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: {name: default-deny-all, namespace: finance}
spec:
  podSelector: {}
  policyTypes: [Ingress, Egress]
---
# 2) The only allowed passage: payment-backend → postgresql:5432
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: "db-isolation-policy"
  namespace: "finance"
spec:
  podSelector:
    matchLabels:
      app: "postgresql"
  policyTypes: [Ingress]
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: "payment-backend"
    ports:
    - protocol: TCP
      port: 5432
⚙ Red Team (Lateral Movement)
  1. The attacker gets RCE in the web frontend pod.
  2. Runs an Nmap scan against the DB pod.
  3. Blue Team: Because of the NetworkPolicy, frontend→DB packets are dropped.

9.2 SOAR and API Orchestration 🔴 Advanced

The digital counterpart of pheromones is the REST API webhook calls that the XDR/SIEM engine makes to other security products.

# SOAR playbook (schematic; API addresses and cs_api are placeholders)
import requests

def isolate_host(ip, mac):
    # 1. Block the IP on the firewall EDL
    requests.post("https://fw.local/api/block", json={"ip": ip}, verify=True)
    # 2. NAC - shut the switch port
    requests.put("https://ise.local/ers/mac/quarantine", json={"mac": mac})
    # 3. EDR - isolate the host
    cs_api.contain_host(ip)
    print("Threat isolated.")

10.2 Probe and Echo Analysis 🟡 Intermediate

The sonar is automated with Scapy. The decoy service's response size and TTL values are recorded as a baseline.

# Network sonar with Scapy
from scapy.all import *

ans, unans = sr(IP(dst="10.0.0.99")/TCP(dport=21, flags="S"), timeout=1)

for snd, rcv in ans:
    if rcv.ttl != 64 or rcv[TCP].window != 8192:
        print("ALERT! The echo changed.")
⚙ Red Team (Misleading the Honeypot)

11.2 HashiCorp Vault & SPIFFE 🟡 Intermediate

In modern architectures the skin is shed with HashiCorp Vault (dynamic DB credentials) or SPIFFE/SPIRE (mTLS rotation). The TTL is chosen to fit the workload's ability to renew: SPIRE's default SVID lifetime is 1 hour; for dynamic database credentials, values from minutes to hours are common. There is no universal “standard” TTL.

# HashiCorp Vault: dynamic DB role (shedding the skin)
vault write database/roles/finance-db-role \
    db_name=postgresql \
    creation_statements="CREATE ROLE \"{{name}}\" WITH LOGIN
        PASSWORD '{{password}}'
        VALID UNTIL '{{expiration}}';" \
    default_ttl="1h" \
    max_ttl="24h"

# When the application asks for a credential:
vault read database/creds/finance-db-role
# When the lease expires, Vault drops this role from the DB (old skin shed).
⚙ Red Team (Token Theft)
  1. In K8s an SA token is stolen through path traversal.
  2. The token is a bound, time-limited projected token; its lifetime is set to 10 minutes (default 1 hour).
  3. When the time runs out or the pod is deleted, the token becomes invalid; the attacker's window is limited to minutes.

  • Bypassing the sensors with a laser or acid.
📚 Case: Cold Boot Research (Princeton, 2008)Halderman et al. showed that DRAM contents stay readable for seconds after power is cut, and for minutes when cooled, and that disk-encryption keys can be recovered from memory. This is the reason for zeroisation and temperature sensors.

12.2 FIPS 140-3 and SRAM 🔴 Advanced

The hardware counterpart of the zeroize protocol is FIPS 140-3 Level 3–4 cryptographic modules (e.g. HSMs): Level 3 requires keys to be zeroised when a cover or door is opened; Level 4 requires a complete tamper envelope plus temperature/voltage protection. When the anti-tamper mesh breaks, a battery-backed chip erases the keys at once.

/* Hardware zeroize signal (C pseudocode) */

void monitor_tamper_sensors() {
    if (read_sensor(CASE_OPEN) || read_sensor(TEMP_ABNORMAL)) {
        /* 1. Zero the SRAM key (DNA fragmentation) */
        memset_secure(MASTER_KEY_ADDR, 0x00, KEY_LENGTH);

        /* 2. Trigger the SSD crypto-erase pin */
        trigger_gpio_pin(SSD_CRYPTO_ERASE_PIN, HIGH);

        /* 3. Blow the e-fuse (permanent brick) */
        blow_efuse(SYSTEM_BOOT_FUSE);
    }
}

13.2 BGP RTBH and Scrubbing 🔴 Advanced

When the attack volume exceeds the link and firewall capacity there are two options: scrubbing (traffic is diverted to a cleaning centre and legitimate traffic comes back — the true counterpart of the reef) and RTBH (all traffic to the victim IP is dropped at the ISP; that IP is sacrificed and the rest of the network is saved).

! Cisco IOS-XR: BGP RTBH (last resort: black hole)
! The attacked IP 192.0.2.100 is routed to Null0 (the black hole)

route-policy RTBH_EXPORT
  if destination in DDoS_VICTIM_IPS then
    ! Blackhole community defined by the ISP (well-known: 65535:666, RFC 7999)
    set community (65000:666) additive
  endif
end-policy

router bgp 65000
 address-family ipv4 unicast
  network 192.0.2.100/32 route-policy RTBH_EXPORT
router static
 address-family ipv4 unicast
  192.0.2.100/32 Null0
⚙ Red Team (NTP Amplification)
  1. The attacker sends spoofed packets to vulnerable NTP servers and launches 100 Gbps of traffic.
  2. Firewall ports fill up and bandwidth is saturated.
  3. Blue Team: Preferably the traffic is diverted to a scrubbing centre. If there is none, or its capacity is exceeded, a /32 with the blackhole community is announced; the ISP drops traffic to that IP inside its own network.

14.1 The Butterflyfish and Misdirection 🟢 Beginner

🐠
Butterflyfish

Biological BasisMany butterflyfish carry a “false eye” spot (ocellus) near the tail, while the real eye is hidden by a dark band.   • The real eye (the real service) cannot be seen from outside.

Red Team

  • Scanning standard ports with Zmap/Masscan.
  • Brute-forcing the discovered port with Hydra.

14.2 Endlessh & SPA (fwknop) 🟡 Intermediate

The butterflyfish's false-eye trap is built with the SSH tarpit Endlessh. When an attacker connects to port 22 it sends an endless, very slow SSH banner; the connection hangs for hours. The real SSH is protected on a hidden port with fwknop (SPA). Hiding a port is not security in itself; the real protection comes from SPA and key-based authentication.

# 1. Endlessh setup (the false eye - tarpit)
# Listens on port 22 and sends one short random banner line every 10 seconds
Port 22
DelayMilliseconds 10000
MaxLineLength 32
MaxClients 4096

# 2. Hiding the real SSH (the real eye - fwknop SPA)
# Port 4434 is DROP (hidden) for everyone on the firewall.
# The client first sends one encrypted, HMAC-authenticated UDP packet (SPA).
# If fwknopd verifies it, it opens a temporary ALLOW rule in iptables.
fwknop -A tcp/4434 -D 192.168.1.50 -a 192.168.1.100
⚙ Red Team (Zmap and Brute Force)
  1. A bot finds the open port 22 (the false eye).
  2. The brute-force tool connects, but because the SSH banner never finishes it cannot start trying passwords.
  3. Blue Team: Endlessh keeps the connection open; the bot's connection threads stay busy. The real administrator enters quietly through the hidden port (the real eye) with SPA.

15.2 Jitter and Packet Chaffing 🔴 Advanced

To slip past the bat in ambush (an attacker watching the traffic), time entropy is added to data transfers with systemd RandomizedDelaySec and chaffing (dummy load) with Python. The attacker's ambush times out.

# 1. Systemd timer - protean timing (random trigger)
# /etc/systemd/system/secure-backup.timer
[Unit]
Description=Critical data sync (with jitter)

[Timer]
OnCalendar=*-*-* 03:00:00
# To defeat the ambush, instead of exactly 03:00
# it fires at a random moment between 03:00 and 05:00 (7200 seconds)
RandomizedDelaySec=7200
Persistent=true

[Install]
WantedBy=timers.target

# 2. Python chaffing (sonar jamming / dummy payload)
import random, os, socket

def send_chaff(sock):
    # Dummy (junk) packets are sent to confuse the attacker's analysis tool
    dummy = os.urandom(random.randint(1024, 4096))
    sock.send(dummy)
⚙ Red Team (Traffic Analysis & Ambush)
  1. With Wireshark the attacker learns that the backup runs at exactly 03:00 every night.
  2. Their script (the bat) lies in wait at 02:59 to cut the network traffic.
  3. Blue Team: 03:00 comes and no data arrives. The attacker's 10-minute script times out. The system sends the real data quietly at 04:12:33, hidden among dummy packets.
